## Что проверяют тесты

Maven: переходы состояний автомобилей и бронирований; неизвестные id; событие с исходным тарифом и временем; округление для 0, 1, 3599, 3600, 3601, 7200, 7201 секунд; сумма и повторная оплата; повтор события; BCrypt и HS256/subject/срок JWT; HTTP 200/404/500 каталога; обновление существующей GPS-позиции; отсутствие пометки outbox при ошибке отправки и пометка после подтверждения.

Сквозной тест: все бизнес-маршруты через Nginx, поля JSON, ограничения DTO, публичный/защищённый доступ, Swagger всех сервисов, регистрация/вход, восемь одновременных reserve (один 200, семь 409), восемь одновременных finish (один 200, семь 409), две одновременные оплаты (200 и 409), откат проигравших транзакций, запись последней GPS-позиции в реальную БД, один счёт при повторной публикации outbox.

Отказные сценарии: Kafka остановлена до finish — API отвечает успешно менее чем за 5 секунд, машина свободна, событие остаётся в MySQL; после старта Kafka счёт появляется. Billing остановлен во время finish — после запуска читает сохранённое Kafka-событие и создаёт счёт. Оба компонента восстановлены, все сервисы healthy.

Сравнение с монолитом: неизменённая копия исходников собрана в `target/monolith-reference`, запущена с отдельным PostgreSQL на порту 18080. Нормализованы только динамические id/метки времени/токены/регистрационные номера. Совпали 31 сценарий, все OpenAPI paths и схемы DTO, агрегированный `/v3/api-docs`. JWT эталонного монолита принят новым сервисом. Временный эталонный стенд после проверки остановлен.

## Область проверки

Это функциональная и интеграционная проверка локальной архитектуры. Не выполнялись нагрузочные испытания, многоброкерный failover, перенос рабочей PostgreSQL-БД или промышленное развёртывание. Созданы отдельные тестовые записи в новом стенде. Асинхронная видимость счета после finish описана в README и migration.md.
